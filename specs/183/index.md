## Problem
Connections exist, but no built-in integration declares one. Every step bills the operator's `claude` login. Slack posts only by webhook. Jira and Slack identities are never looked up. A Claude token revoked mid-life leaves every run "unavailable" forever, with the row still "connected".

## Decisions
1. Person pastes `claude setup-token` output into the Claude row of the Integrations tab. Their steps run with `CLAUDE_CODE_OAUTH_TOKEN`.
2. Jira and Slack rows fill themselves from the person's email on start or reload. Person cannot edit them. A failed lookup shows the row "missing", detail = vendor's reason.
3. Token ≤30 days from its end → `connection.expiring` logged, at most once per connection per day.
4. Agent refuses the token → `connection.failed` logged, row "failed", runtime reloads, nothing runs until a re-paste. No round.
- Auth detected in runner, not kit: kit may log only `agent.*`/`step.*` and cannot import the store. Converge already reads `result.reason` for `agent.limited`.
- `resolve` throws when it cannot look up (no `slackBotToken`, Jira refusal) and returns null when nobody matches. Engine cannot name a vendor's secret, so the reason travels in the throw.
- A stored connection is judged even when not required: a failed Claude token must stop runs, not fall back to the operator login.
- No stored connection → no `personEnv`, today's login. Existing setups unchanged.
