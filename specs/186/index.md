## Problem

On one instance, person A's step can read B's worktree under `$TMPDIR/landrace/<repo>/worktrees/<B>/` and B's transcripts under `~/.claude/projects/`, with Bash in a write step or Read in a read step. Today every tier is denied only `CREDENTIALS_ROOT`, through the Claude integration's `deniedPaths`.

## Decisions

- When A's step starts, the engine builds A's deny list: the credentials root, each other person's scope dir, and the transcript dirs of runs under each of those dirs. The Claude CLI refuses a Read, and the sandbox refuses a Bash read, of any path on the list. A's own paths are never listed.
- Locally there is one person and no others, so the list is just the credentials root. Claude's argv stays exactly as it is today.
- `claudeProjectDirOf` goes in `integrations/claude/index.ts`, not in `src/`. `tests/boundaries.test.ts` fails on any vendor name under `src/`, so the engine asks the integration (`transcriptsUnder`) and stays vendor-neutral.
- `denyPaths` is a function, not `string[]`. The item says the list is computed when each step starts: B's transcript dirs appear after A's executor is built, and the roster changes on `sync`.
- Project dirs match on a `-` boundary: the name equals the encoded dir, or starts with it followed by `-`. So `bob` never matches `bobby`. An encoding collision denies more, never less.
- An absolute path is written as a `Read(//…)` rule, because `/…` is read relative to the settings file.
- A computed path holding `(`, `)` or a control character refuses the run. Dropping it would leave that person readable.
- If the agent cannot keep a deny list (`sandboxProblems` objects, as Codex's does) and other people are present, the run is refused. Alone, it runs as today.

## Technical design

- `src/people/isolation.ts` (new): `scopeOf(person)`, the existing `encodeURIComponent` scope. `denyForPerson(self, others, { worktrees, credentials })` returns the credentials root plus `<worktrees>/<scopeOf(other)>` for each other person, with self excluded and duplicates dropped.
- `src/namespace.ts`: adds `ExecutorContext.denyPaths?: () => Promise<string[]>`, `KitSettings.denyPaths` (same type) and `BuildOptions.others?: () => Person[]`.
- `src/kit/executor.ts`: `create` passes `denyPaths` to `build`, for the screener too. `run` awaits it before `prepare`, adds `transcriptsUnder(path)` for each absolute path, and merges the result into `plan.sandbox.deny` for every tier. It refuses bad paths and agents that cannot keep the list, as above. Adds protected optional `transcriptsUnder?(dir): Promise<string[]>`.
- `integrations/claude/index.ts`: exported `claudeProjectDirOf(cwd, home?)` replaces `projectDir`. `transcriptsUnder` lists the matching dirs under `<home>/.claude/projects`. `readRules` writes absolute paths as `//`.
- `src/cli/start.ts`: the roster's `build` passes `others` (`roster.people()` minus self). `ectx.denyPaths` calls `denyForPerson` with worktrees `join(sandboxRoot(root), "worktrees")` and credentials `CREDENTIALS_ROOT`. The sandbox scope uses `scopeOf`.
- `docs/security.md`: new section "People on one instance", stating the residual risk as in spec §9.
