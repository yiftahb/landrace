## Problem
Forge credentials are paste-only today. No OAuth path, and no refresh: a GitLab OAuth token expires after 2 h and nothing renews it. Design Decision §4 wants OAuth when the instance has that provider's app configured.

## Decisions
- Flow: Integrations tab → GitLab row shows **Connect with GitLab** link (no paste form) → provider consent → `GET /connect/gitlab/callback` → token checked and stored → 302 `/#/integrations` → row Connected.
- OAuth offered only when both client-id and client-secret secrets non-empty in `ctx.secrets`; otherwise paste form, unchanged.
- `oauth` is a function of `ctx`: GitLab URLs need the `gitlabBaseUrl` secret. So `beginConnect`/`finishConnect`/`refreshIfNeeded` also take `ctx`.
- State: 32 random bytes, base64url, in memory, 10 min TTL, bound to person, connection id, verifier and redirect URI. Single-use: deleted on first lookup.
- Callback runs `def.check` like a paste. Failure → 409/502 plain text, scrubbed. Stores nothing.
- Redirect target `/#/integrations`: the page's real tab hash. Plan's `/#integrations` opens nothing.
- Token request: form POST, `Accept: application/json`. Response with no `access_token` → refused, naming `error`/`error_description` only, never the body.
- No `expires_in` (GitHub OAuth app) → no `expiresAt`, never refreshed.
- Refresh keeps `connectedAt` and the old refresh token when none is returned.
- Refresher, local person, every 60 s:
  - success → redact the new token, store it (skipped if the stored refresh token changed meanwhile), write the new value into the live secret map for each per-person secret the environment did not set, log `connection.refreshed`;
  - token endpoint 4xx or `error` → store `failure`/`failedAt`, log `connection.failed`, reload (runs stop, row Not working);
  - network error or 5xx → log `connection.failed`, retry next pass.
- No stage, trigger, route or admission change.
