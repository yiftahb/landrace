## Problem
When the local person is missing a connection, `start` refuses (`assertLocalUsable`, `assertPersonReady`). The only fix is to edit `.env` or the store by hand, then restart. There is no paste UI and no reload. Case: one per-person secret and an empty store → `start` exits with `connection.missing`.

## Decisions
- Start with a connection missing → front door up, page shows only the Integrations tab. One row per defined connection: label, state, detail.
- Credential row: paste form with its `hint`. Submit → `def.check` → stored → runtime rebuilt → board shows, next wake ticks.
- Identity row is read-only and shows state only, since `MeView` carries no values. Pasting one is refused, because identities get looked up.
- Disconnect → rebuild. Losing a required connection hides the board and stops ticks.
- Only `connection.*` problems gate. Config, workflow, hook and `connection.duplicate` problems still refuse start.
- Per-person var unanswered: the gate loads the workspace with `""` for it, only to import hooks and learn connections. Nothing from that load runs. The schema is checked before substitution, so `""` is safe.
- `--once`, `--headless` while unready: refuse as today. There is no door to connect through.
- Failing `check` → 409 with the reason scrubbed; nothing stored.
- Failed reload: connection stays stored, route answers 502 with the reason scrubbed, previous runtime kept.
- Old runtime starts no new pass; its in-flight runs finish under their item locks. They are not aborted, because a connect must not kill a paid step. Concurrency can briefly overshoot until Task 6's shared pool.
- One logger, one telemetry sink and one stop controller per process, so events survive reloads and Ctrl-C stops everything.
- `/mcp` while unready → 503. A reload drops sessions; clients reconnect.

## Technical design
- `src/people/panel.ts` — `createPeoplePanel`, `MeView`, `PeoplePanel` as the plan types them. `connect` requires exactly `def.fields`, none empty, and redacts values before `check`. It stores `source: "paste"`, logs `person.connected` `{ connection }`, calls `onChange`. Unknown id or identity → `Refusal`.
- `src/people/resolve.ts` — export `statusOf` as `connectionStatus`; `me` lists every defined connection.
- `src/runner/slot.ts` — `createRuntimeSlot`: swaps only when the build succeeds.
- `src/cli/start.ts`:
  - `localGate` (store, hooks, `resolvePerson`).
  - Slot build: gate → `buildWorkspaceRuntime` → `runPreflights`, or null when unready.
  - Board, goto, panel, admit, refresh and MCP endpoint built once per runtime; routes go to the current one.
  - Schedule `run` reads `slot.current()`; null → no pass.
  - `onChange` → `reload` → `wake`.
  - New `BuildOptions.log`, `BuildOptions.stop`.
- `src/ui/server.ts` — `UiOptions.people: { panel; caller(req) }`. Routes `GET /people/me`, `POST /connect/:id`, `POST /disconnect/:id`. `bodyOf` takes a limit (16 KiB → 413). `UiOptions.ready()`; `/board.json` answers `{ ready: false }` while unready.
- `src/ui/page.ts` — Integrations tab in `APP_JS`; board hidden while unready.
- `src/namespace.ts` — `EventName` gains `person.connected`, `person.disconnected`. New `MeView`, `PeoplePanel`, `RuntimeSlot`, `UiOptions.people`, `UiOptions.ready`, `BuildOptions.log`, `BuildOptions.stop`.
- `docs/board-pane.md` — Integrations tab. `docs/cli.md` — `start` with unready connections.

## Done when
- `GET /people/me` with a required connection missing → that row `missing`, `ready: false`.
- `POST /connect/x` → `state: "connected"`; `/people/me` then `ready: true`.
- No action header → 403. Body > 16 KiB → 413. Identity or unknown id → 409. Failing `check` → 409, store unchanged.
- Stored file holds the value. No log line, stdout row or OTEL record does.
- `slot.reload` swaps `current()`. A throwing build keeps the previous runtime and propagates.
- `start` with a missing per-person secret, or var → front door serves, `/board.json` `{ ready: false }`, `/mcp` 503, no `tick.started`. After connect, next wake ticks.
- Disconnecting a required connection → `{ ready: false }`, no further `tick.started`.
- `start --once` while unready → exit 1, `connection.missing`.
- A `.env`-only setup starts and ticks unchanged.
- `pnpm test && pnpm typecheck && pnpm lint && pnpm build` pass. Live check as Task 4 Step 4.
