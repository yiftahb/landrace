## Problem
Write step writes shared `.git` and worktree's `.git` file. Engine then runs git outside sandbox, whole env. Planted hook, `core.hooksPath`, `core.fsmonitor`, filter, rewritten `.git` file or `commondir` runs step code on engine `checkout`/`status`/`worktree add`, and on operator's `git pull`. Reproduced, git 2.50.1.

## Decisions
- Person sees nothing new on success. Write step on integration without `keepsDenyWrite`: `start` and `validate` refuse, naming step. Per-run refusal stays as backstop.
- Round 2, from review: `isolation: none` covered; startup refusal; `GIT_COMMON_DIR` pinned; live check runs whole git flow; `GIT_GUARD_ARGS` on every engine git spawn.
- Admin folder holding `config.worktree` halts. Engine never makes one. With `extensions.worktreeConfig` on, a renamed-in folder's copy could set filters, so this halt keeps the rename chain at HEAD, index, logs.
- Engine computes list. Worktree `.git` file untrusted.
- List merged whatever `agent.sandbox.deny` says.
- `keepsDenyWrite` default false: fail closed.
- Admin folder lookup: one `<common>/worktrees/*/gitdir` naming `<worktree>/.git`. None or two halts.
- Filters closed by deny list alone. Overriding `filter.*` breaks `git lfs install --local`.
- Push rewriting unchanged. Token scoped to post-rewrite URL `originPushUrl` reads.
- No `validate` check for planted hooks: it would flag operator's own. Docs give inspection commands.
